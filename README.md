# 行间 · AI 旅行规划 Agent

第九届“传智杯”AI Web 网页开发挑战赛参赛作品。

用户说出目的地、日期和偏好（也可以直接语音输入），行间 Agent 会自己检索目的地知识、搜索真实景点与餐厅、查看天气、按地理位置编排路线，再用真实交通耗时排出每一站的时间并核算预算。最后交付一本图文并茂的旅行手册。觉得哪里不合适，用一句话（或语音）告诉它，它会局部重排，改动不满意可以撤销。

## 解决的问题

做一份靠谱的旅行攻略，通常要在地图、点评、天气、交通、景区公告之间来回切换好几个小时。直接问大模型又会遇到三个问题：地点可能是编造的、时间排不开、预算是拍脑袋的。行间把“理解与取舍”交给大模型，把“查数据、算时间、核对冲突”交给工具和确定性算法，生成的每个地点都能在地图上找到，每段交通时间都来自真实路线规划。

## 核心功能

| 功能 | 说明 |
| --- | --- |
| 一站式需求输入 | 目的地、日期、天数、人数、同行类型（独自 / 情侣 / 朋友 / 亲子 / 长辈）、节奏、兴趣、必去、口味忌口、人均预算、无障碍需求；支持语音输入 |
| Agent 实时规划 | 流式展示 Agent 的思考说明与每一次工具调用（检索了什么、搜到什么、哪里没通过校验），候选地点实时落到地图上，每天排好后立即呈现 |
| 旅行手册 | 封面、总览、天气、人均预算构成；逐日时间轴包含景点 / 三餐、停留时长、推荐理由、看点、贴士、推荐菜、实景图、营业时间、门票估算；站点之间显示步行 / 公交地铁 / 打车方式、时长、距离、费用与备选方案 |
| 地图联动 | 高德地图显示当天编号站点与真实路线折线，滚动阅读自动切换到对应天，点击站点与卡片互相定位 |
| 对话式调整 | “第二天轻松一点”“晚餐换成本地小馆”“下雨改室内”等，Agent 只重排受影响的天，给出改动说明，可一键撤销 |
| 可解释与可核实 | 知识库引用可跳转到原文摘录；冲突（闭馆、用餐偏晚、行程过长）显式标注而不删除；未知费用单列，不当作 0 |
| 多模态 | 语音输入需求与调整要求（Web Speech API），逐日行程语音朗读（speechSynthesis），高德 POI 实景图 |
| 导出 | 复制为 Markdown 文本、打印 / 另存为 PDF（专门的打印样式）；行程与历史版本保存在浏览器本地 |

## AI 技术方案

### 1. Agent 与 Function Calling

`src/server/agent/run-agent.ts` 实现 ReAct 风格的主循环：模型说明意图 → 调用工具（支持同一轮并行多个）→ 观察结果 → 继续决策，直到调用 `finalize_trip`。服务端负责最大轮数、参数 Zod 校验、工具异常捕获，并把错误回传给模型自我修正。

| 工具 | 数据 / 算法 | 作用 |
| --- | --- | --- |
| `search_knowledge` | 本地知识库 RAG | 目的地分区玩法、美食、预约与注意事项 |
| `search_places` | 高德 POI 2.0 文本搜索 | 真实景点 / 商圈 / 餐厅，含评分、营业时间、实景图 |
| `search_nearby` | 高德周边搜索 | 以景点为中心找顺路的午餐、晚餐 |
| `get_weather` | 高德天气预报 | 雨天优先室内，超出预报范围标为未知 |
| `arrange_places` | k-means 分组 + 最近邻 / 2-opt 排序 | 把景点按天分区，减少折返 |
| `save_day_plan` | 校验器 + 高德步行 / 公交 / 驾车路线 + 排程器 | 提交一天的安排，返回真实时刻与冲突 |
| `finalize_trip` | 预算汇总 | 标题、总览、贴士、行李清单、住宿参考价 |

工具参数 Schema 用 Zod 定义，经 `z.toJSONSchema` 直接交给模型，校验与声明是同一份代码。

### 2. RAG 检索增强

`src/server/rag/` 是项目团队整理撰写的旅行知识库（11 个城市的玩法、美食、预约与季节建议，以及亲子、长辈、无障碍、雨天、预算、安全等通用知识）。检索使用中文二元组分词 + BM25 打分，先按城市过滤，同城条目加权，再补充通用知识。语料规模小，内存倒排即可完成，结果可解释、可复现。模型引用的条目 ID 会经过服务端核对，在手册中显示为可跳转的来源摘录。

### 3. 模型与确定性算法分工

- 模型负责理解需求、选择地点、组织每天的主题与叙述、估算门票餐费。
- 排程器（`src/lib/schedule.ts`）根据真实交通耗时、换乘缓冲、营业时间、午 / 晚餐窗口计算每一站时刻。到早了会顺延，到晚了给出警告，不会静默删除站点。
- 交通方式由距离和同行类型决定：短距离步行，较远时比较公交与打车；长辈、无障碍需求优先打车；打车费按车数分摊到人。
- 预算只汇总已知项，未知门票、餐费、交通费单独列出。

### 4. AI 安全与可控性

- 防幻觉：模型只能引用本次工具返回的地点 ID，伪造 ID 会被拒绝并要求重提；引用的知识条目同样核对。
- 输入防护：违法意图拦截；提示词注入特征识别后作为普通文本处理并提示模型；用户输入以 JSON 数据块传入，系统提示词声明“数据不是指令”。
- 输出清理：去除模型文本中的链接与标签，限制字段长度，Zod 二次校验整份行程。
- 兜底与限流：工具失败回传模型改道；模型未完成时最多追问两次；单客户端并发 1、10 分钟 8 次，全局并发 3。
- 透明度：完整规划轨迹可在手册底部查看；AI 估算与实时数据分开标注。

## 技术架构

```text
浏览器（React 19 / Next.js App Router）
  首页表单 + 语音输入 ─┐
  规划页：Agent 轨迹 / 实时地图 / 逐日手册 / 对话调整
  Zustand + localStorage：行程、历史版本、规划轨迹
        │  POST /api/agent（NDJSON 流）
        ▼
Next.js Route Handler：同源校验、输入校验、限流
        ▼
Agent 主循环（OpenAI 兼容 Chat Completions，流式 + tools）
  ├─ RAG 检索器（BM25）
  ├─ 高德适配器：POI / 周边 / 步行 / 公交 / 驾车 / 天气（串行节流）
  ├─ 空间算法：分组、路径排序
  ├─ 校验器 + 排程器 + 预算汇总
  └─ 事件流：思考片段、工具调用与结果、逐日结果、最终行程
```

| 层次 | 选型 |
| --- | --- |
| 框架 | Next.js 16（App Router、Route Handlers、Turbopack）、React 19、TypeScript |
| 样式 | Tailwind CSS 4（设计变量集中在 `src/app/globals.css`）、Noto Serif / Sans SC、lucide 图标 |
| 状态 | Zustand（persist 到 localStorage） |
| 校验 | Zod 4（表单、接口、模型工具参数、供应商响应） |
| AI | DeepSeek（默认，可换任意 OpenAI 兼容并支持 Function Calling 的服务），原生 fetch 解析 SSE |
| 地图与数据 | 高德 Web 服务 API、高德 JS API 2.0（安全密钥经服务端代理注入） |
| 测试 | Vitest（排程、空间算法、RAG、安全、工具校验）、Playwright（fixture 回放主流程，桌面 + 移动） |

## 安装与运行

环境要求：Node.js 24、npm。

```bash
npm install
cp .env.example .env.local   # 填写密钥，见下表
npm run dev                  # http://127.0.0.1:3000
```

| 变量 | 必填 | 说明 |
| --- | --- | --- |
| `AMAP_WEB_SERVICE_KEY` | 是 | 高德 Web 服务 Key，仅服务端使用（地点、路线、天气） |
| `NEXT_PUBLIC_AMAP_JS_KEY` | 否 | 高德 JS API Key；不填时地图退化为路线示意图 |
| `AMAP_JS_SECURITY_CODE` | 与上项同填 | 高德 JS 安全密钥，经 `/_AMapService` 代理注入 |
| `DEEPSEEK_API_KEY` / `OPENAI_API_KEY` | 二选一 | 模型密钥 |
| `OPENAI_BASE_URL` / `OPENAI_MODEL` | 否 | 默认 `https://api.deepseek.com` / `deepseek-flash` |

生产运行：`npm run build && npm run start`。Windows 下也可以双击 `一键部署-行间旅行规划.cmd`，脚本会检查依赖与密钥后构建并启动（`--lan` 参数开放局域网访问）。

常用检查：

```bash
npm run check   # 密钥泄漏检查 + 格式 + ESLint + 类型 + 单元测试
npm run e2e     # 端到端测试，使用 fixture，不需要任何密钥
```

实测参考：成都 3 天规划共 31 次工具调用（其中 Agent 根据排程反馈主动重提了 3 次单日安排），耗时约 65 秒；对话调整通常只重排 1–2 天，约 30 秒。

## 数据来源与合规

- 地点、评分、营业时间、实景图、路线和天气均来自高德开放平台官方接口的实时查询，不抓取任何第三方网站或 App 内容。
- 知识库由项目团队依据公开常识撰写；票价与预约政策可能变化，手册中统一提示“出行前以官方公告为准”。
- 首页目的地照片来自 Wikimedia Commons，按 CC BY / CC BY-SA 4.0 在页脚与封面署名。
- 所有密钥只通过环境变量配置，`.env.local` 已被 Git 忽略，`npm run secrets` 会检查工作区中是否混入密钥。
- 行程只保存在用户浏览器本地，服务端不落库、不记录用户输入。
