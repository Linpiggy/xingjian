# 行间 · AI 旅行规划 Agent

第九届“传智杯”AI Web 网页开发挑战赛参赛作品。

用户说出目的地、日期和偏好（也可以直接语音输入），行间 Agent 会自己检索目的地知识、搜索真实景点与餐厅、查看天气、按地理位置编排路线，再用真实交通耗时排出每一站的时间并核算预算。最后交付一本图文并茂的旅行手册。觉得哪里不合适，用一句话（或语音）告诉它，它会局部重排，改动不满意可以撤销。

## 解决的问题

做一份靠谱的旅行攻略，通常要在地图、点评、天气、交通、景区公告之间来回切换好几个小时。直接问大模型又会遇到三个问题：地点可能是编造的、时间排不开、预算是拍脑袋的。行间把“理解与取舍”交给大模型，把“查数据、算时间、核对冲突”交给工具和确定性算法，生成的每个地点都能在地图上找到，每段交通时间都来自真实路线规划。

## 核心功能

| 功能 | 说明 |
| --- | --- |
| 首页 | 滚动叙事：首屏标题逐行升起、照片视差；“Agent 怎么做功课”整段吸顶，随滚动逐步演示检索、查地点、看天气、画路线、校验修正；目的地长廊由纵向滚动驱动横向平移（窄屏改为原生横滑）；尊重系统“减少动态效果”设置 |
| 拍照识景 | 上传一张在网上看到或自己拍的旅行照片，视觉模型识别具体地点与风格（山水、古镇、夜景……），推荐 1–3 个合适的城市，一键填入目的地、兴趣和补充说明；上传前在浏览器内压缩并去除 EXIF 位置信息 |
| 一站式需求输入 | 目的地、日期（月历直接高亮整段行程）、天数、人数、同行类型（独自 / 情侣 / 朋友 / 亲子 / 长辈）、节奏、兴趣、必去、口味忌口、人均预算、无障碍需求；支持语音输入 |
| 往返车次 | 填写出发城市后，Agent 查询高德跨城交通数据，推荐去程、返程高铁/动车车次（站点、时刻、各席别票价区间），第一天从到站时间开始安排、最后一天在发车前 1.5 小时结束，车票计入预算，并提供 12306 购票入口（余票以 12306 为准） |
| 抵达、返程与住宿 | 填写第一天几点到、最后一天几点走和已订酒店；未订时 Agent 在行程重心附近推荐住处。每天从住处出发、回到住处，交通按真实路线计算；第一天按抵达时间开始，最后一天留足赶车时间，必吃正餐随之调整 |
| Agent 实时规划 | 流式展示 Agent 的思考说明与每一次工具调用（检索了什么、搜到什么、哪里没通过校验），候选地点实时落到地图上，每天排好后立即呈现 |
| 旅行手册 | 封面、总览、天气、人均预算构成；逐日时间轴包含景点 / 三餐、停留时长、推荐理由、看点、贴士、推荐菜、实景图、营业时间、门票估算；站点之间显示步行 / 公交地铁 / 打车方式、时长、距离、费用与备选方案 |
| 地图 | 每天的章节以当天路线图开篇（编号站点、住处、真实路线折线，进入视口才加载）；点击站点定位到卡片。悬浮“地图”按钮打开当前阅读那天的全屏地图，站点列表与地图联动，可切换天、跳回详情 |
| 对话式调整 | “第二天轻松一点”“晚餐换成本地小馆”“下雨改室内”等，Agent 只重排受影响的天，给出改动说明，可一键撤销 |
| 推荐菜与门票核对 | 每顿饭推荐 2–4 道具体菜品，优先取自高德收录的该店招牌菜并标“招牌”，附订座电话；收费景点可联网核对门票（只采信政府、景区官网等官方来源），价格旁显示来源链接与核对日期，未核对的明确标“估” |
| 行前问答 | 对话栏切到“问问 AI”，可以问“要提前预约吗”“附近有便利店吗”“下雨去哪”。问答 Agent 结合当前行程、知识库和高德实时查询流式作答，展示查询步骤，并标注引用的知识条目与是否用了实时数据；问答记录随行程保存 |
| 分享与长图 | 一键生成只读分享链接（行程压缩进链接 # 之后的部分，不经服务器存储，链接约 1 万字符），打开即可查看完整手册与地图并存为自己的行程；同时生成带每站实景图的杂志风行程长图（Canvas 绘制，图片经同源代理避免画布污染），电脑可下载、手机可通过系统分享保存 |
| 手动微调 | 每一站都可以锁定（AI 调整时必须保留）、上移 / 下移、增减停留时长、删除，或从 Agent 检索过的候选里“换一个”（按距离排序）。手动调整不调用大模型，只用真实路线重新排出当天时刻，几秒完成，同样可撤销 |
| 示例手册 | 首页提供两份 Agent 实际生成的手册（杭州 2 天情侣、成都 3 天亲子），无需密钥即可翻看和手动编辑 |
| 可解释与可核实 | 知识库引用可跳转到原文摘录；冲突（闭馆、用餐偏晚、行程过长）显式标注而不删除；未知费用单列，不当作 0 |
| 多模态 | 照片识别（视觉大模型）、语音输入需求与调整要求（Web Speech API）、逐日行程语音朗读（speechSynthesis）、高德 POI 实景图、Canvas 生成行程长图 |
| 导出 | 复制为 Markdown 文本、打印 / 另存为 PDF（专门的打印样式）；行程与历史版本保存在浏览器本地 |

## AI 技术方案

### 1. Agent 与 Function Calling

`src/server/agent/run-agent.ts` 实现 ReAct 风格的主循环：模型说明意图 → 调用工具（支持同一轮并行多个）→ 观察结果 → 继续决策，直到调用 `finalize_trip`。服务端负责最大轮数、参数 Zod 校验、工具异常捕获，并把错误回传给模型自我修正。

| 工具 | 数据 / 算法 | 作用 |
| --- | --- | --- |
| `search_knowledge` | 本地知识库 RAG | 目的地分区玩法、美食、预约与注意事项 |
| `search_places` | 高德 POI 2.0 文本搜索 | 真实景点 / 商圈 / 餐厅，含评分、营业时间、实景图 |
| `search_nearby` | 高德周边搜索 | 以景点为中心找顺路的午餐、晚餐 |
| `get_weather` | 高德天气预报 | 雨天优先室内，超出预报范围标为未知 |
| `arrange_places` | k-means 分组 + 最近邻 / 2-opt 排序 | 把景点按天分区，减少折返 |
| `set_hotel` | 高德地点 + 服务端校验 | 多日行程先定住处，此后每天自动计算往返交通；换酒店时自动重算未改动的天 |
| `search_trains` / `set_trains` | 高德跨城公交规划（铁路分段） | 查询并选定往返车次；只能选择查询结果中的车次，选定后约束首末两天的时间与必吃正餐 |
| `verify_ticket` | 联网搜索（Tavily，可选） | 核对门票价格与预约政策，结果按官方来源分级；行程只能引用本次检索到的链接 |
| `save_day_plan` | 校验器 + 高德步行 / 公交 / 驾车路线 + 排程器 | 提交一天的安排，返回真实时刻与冲突 |
| `finalize_trip` | 预算汇总 | 标题、总览、贴士、行李清单、住宿参考价 |

工具参数 Schema 用 Zod 定义，经 `z.toJSONSchema` 直接交给模型，校验与声明是同一份代码。

`save_day_plan` 把排程结果和冲突（闭馆、用餐偏晚、行程超过 22 点、赶不上返程）回传给模型，模型据此调整顺序或删减后重提；同一天最多重提 3 次，之后要求模型接受并把剩余冲突留给用户，避免死循环。调整模式下，用户锁定的站点若被移出当天，提交会被拒绝。

### 2. RAG 检索增强

`src/server/rag/` 是项目团队整理撰写的旅行知识库（11 个城市的玩法、美食、预约与季节建议，以及亲子、长辈、无障碍、雨天、预算、安全等通用知识）。检索使用中文二元组分词 + BM25 打分，先按城市过滤，同城条目加权，再补充通用知识。语料规模小，内存倒排即可完成，结果可解释、可复现。模型引用的条目 ID 会经过服务端核对，在手册中显示为可跳转的来源摘录。

### 3. 模型与确定性算法分工

- 模型负责理解需求、选择地点、组织每天的主题与叙述、估算门票餐费。
- 排程器（`src/lib/schedule.ts`）根据真实交通耗时、换乘缓冲、营业时间、午 / 晚餐窗口计算每一站时刻。到早了会顺延，到晚了给出警告，不会静默删除站点。
- 交通方式由距离和同行类型决定：短距离步行，较远时比较公交与打车；长辈、无障碍需求优先打车；打车费按车数分摊到人。
- 预算只汇总已知项，未知门票、餐费、交通费单独列出；住宿按“每间每晚参考价 × 晚数 × 房间数 ÷ 人数”分摊；往返车票按二等座最高档票价计入，偏保守。
- 第一天抵达后预留 60 分钟出站放行李，最后一天预留 1.5 小时赶车；必吃正餐按抵达 / 返程时间自动放宽（例如 17:00 的车不要求晚餐），校验器与提示词共用同一条规则。

### 4. AI 安全与可控性

- 防幻觉：模型只能引用本次工具返回的地点 ID、车次 ID 与网页来源 ID，伪造会被拒绝并要求重提；引用的知识条目同样核对。
- 输入防护：违法意图拦截；提示词注入特征识别后作为普通文本处理并提示模型；用户输入以 JSON 数据块传入，系统提示词声明“数据不是指令”。
- 输出清理：去除模型文本中的链接与标签，限制字段长度，Zod 二次校验整份行程。
- 兜底与限流：工具失败回传模型改道；模型未完成时最多追问两次；单客户端并发 1、10 分钟 8 次，全局并发 3。
- 透明度：完整规划轨迹可在手册底部查看；AI 估算与实时数据分开标注。

### 5. 行前问答 Agent 与多模态

- 问答 Agent（`src/server/agent/ask-agent.ts`）复用规划 Agent 的检索类工具（知识库、高德地点 / 周边、天气），但不提供任何修改行程的工具；行程以 JSON 数据块注入上下文，回答流式返回。模型在调用工具前输出的过渡文字会被丢弃，只保留最终回答；检索到的知识条目与是否使用实时数据随回答一起返回。
- 拍照识景（`src/server/llm/vision.ts`）调用 OpenAI 兼容的多模态接口（默认智谱 GLM-4V-Flash），要求模型只输出 JSON；服务端提取 JSON、用 Zod 宽松校验（非法字段回退为安全默认值、兴趣只保留预设列表内的值），并对识别文本做内容安全检查。照片只转发给模型，不落盘。

### 6. MCP Server

`scripts/mcp-server.ts` 按 Model Context Protocol（stdio，JSON-RPC 2.0）把行间的能力暴露给 Claude Desktop、Cursor 等 MCP 客户端，无额外依赖：

| 工具 | 说明 |
| --- | --- |
| `search_travel_knowledge` | 检索行间旅行知识库 |
| `search_places` / `search_nearby` | 高德地点与周边检索 |
| `get_weather` | 城市 4 天天气预报 |
| `plan_trip` | 调用完整的规划 Agent，返回 Markdown 旅行手册 |

客户端配置示例（`cwd` 为项目根目录，密钥从 `.env.local` 读取）：

```json
{
  "mcpServers": {
    "xingjian-travel": {
      "command": "npx",
      "args": ["tsx", "scripts/mcp-server.ts"],
      "cwd": "D:/path/to/传智杯-AI-WEB"
    }
  }
}
```

### 7. 对照评测

`npm run evaluate` 把同样的需求分别交给“直接问大模型”和行间 Agent，用同一套基于高德实时数据的检查打分，结果写入 [docs/evaluation.md](docs/evaluation.md)。最近一次 4 个用例（含知识库未覆盖的青岛）的汇总：

| 方案 | 地点可核实率 | 正餐覆盖率 | 交通不可行段 | 营业时间冲突 | 平均耗时 |
| --- | --- | --- | --- | --- | --- |
| 直接问大模型 | 83%（44/53） | 89% | 11/30 | 3/28 | 2 s |
| 行间 Agent | 98%（50/51） | 100% | 0/40 | 3/33 | 56 s |

Agent 用约 1 分钟的工具调用换来了可核实的地点和排得开的时间；营业时间冲突两者相当，评测文档说明了该指标的局限。样本量小，模型输出有随机性，数值仅说明方法差异。

## 技术架构

```text
浏览器（React 19 / Next.js App Router）
  首页表单 + 语音输入 ─┐
  规划页：Agent 轨迹 / 实时地图 / 逐日手册 / 对话调整
  Zustand + localStorage：行程、历史版本、规划轨迹
        │  POST /api/agent（规划/调整，NDJSON 流）  POST /api/ask（问答，NDJSON 流）
        │  POST /api/vision（拍照识景）           POST /api/reschedule（手动调整，不调用模型）
        ▼
Next.js Route Handler：同源校验、输入校验、限流
        ▼
Agent 主循环（OpenAI 兼容 Chat Completions，流式 + tools）
  ├─ RAG 检索器（BM25）
  ├─ 高德适配器：POI / 周边 / 步行 / 公交 / 驾车 / 天气（串行节流）
  ├─ 空间算法：分组、路径排序
  ├─ 校验器 + 排程器 + 预算汇总
  ├─ 住宿：每天往返交通、抵达 / 返程约束
  └─ 事件流：思考片段、工具调用与结果、逐日结果、最终行程
```

| 测试 | Vitest（排程、空间算法、RAG、安全、工具校验）、Playwright（fixture 回放主流程，桌面 + 移动） |

## 安装与运行

环境要求：Node.js 24、npm。依赖清单与精确版本见 `package.json` 和 `package-lock.json`（运行时依赖仅 Next.js、React、Zod、Zustand、Motion、fflate、lucide 图标、高德 JS 加载器与两款开源中文字体）；环境变量模板见 `.env.example`。

```bash
npm install
cp .env.example .env.local   # 填写密钥，见下表
npm run dev                  # http://127.0.0.1:3000
```

| 变量 | 必填 | 说明 |
| --- | --- | --- |
| `AMAP_WEB_SERVICE_KEY` | 是 | 高德 Web 服务 Key，仅服务端使用（地点、路线、天气） |
| `NEXT_PUBLIC_AMAP_JS_KEY` | 否 | 高德 JS API Key；不填时地图退化为路线示意图 |
| `AMAP_JS_SECURITY_CODE` | 与上项同填 | 高德 JS 安全密钥，经 `/_AMapService` 代理注入 |
| `DEEPSEEK_API_KEY` / `OPENAI_API_KEY` | 二选一 | 模型密钥 |
| `OPENAI_BASE_URL` / `OPENAI_MODEL` | 否 | 默认 `https://api.deepseek.com` / `deepseek-flash` |
| `TAVILY_API_KEY` | 否 | 联网搜索密钥（门票官方核对）；不填时门票按 AI 估算并标注 |
| `VISION_API_KEY` | 否 | 视觉模型密钥（拍照识景）；不填时该功能提示“暂未开启”，其他功能不受影响 |
| `VISION_BASE_URL` / `VISION_MODEL` | 否 | 默认 `https://open.bigmodel.cn/api/paas/v4` / `glm-4v-flash`，可换成其他 OpenAI 兼容的多模态服务 |

生产运行：`npm run build && npm run start`。Windows 下也可以双击 `一键部署-行间旅行规划.cmd`，脚本会检查依赖与密钥后构建并启动（`--lan` 参数开放局域网访问）。

常用检查：

```bash
npm run check   # 密钥泄漏检查 + 格式 + ESLint + 类型 + 单元测试
npm run e2e     # 端到端测试，使用 fixture，不需要任何密钥
npm run evaluate  # 对照评测，会真实调用模型与高德（约 10 分钟）
```
