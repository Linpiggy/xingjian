# AI 旅行规划工作台

面向第九届“传智杯”AI WEB 网页开发挑战赛的旅行规划 Web 项目。重点是可编辑、可解释的完整行程，而不是让 AI 输出一篇攻略。

> 当前阶段：最小闭环实现中。已创建应用代码与锁定依赖，格式与静态检查、59 个离线单元测试、22 个 E2E 检查及生产构建已通过；实际应用草稿 API 已通过真实联调，桌面真实 JS 底图与点选实测已通过（窄屏／工作台真实路线绘制待验），见 [测试记录](docs/testing.md)。2026-10-12 高德地点、附近餐厅、步行与公交已通过 5 次真实请求的冒烟测试。和风天气按用户要求暂假设可接入，未实测；费用、额度与公开展示许可仍待确认。Figma 已创建 3 个桌面页面、1 个窄屏工作台及 4 个状态组件，当前是原生可编辑的静态设计稿，不是可执行应用。详见 [接口核验记录](docs/api-verification.md)。

## 1. 产品目标与边界

用户输入目的地、日期、人数、预算、兴趣、节奏、住宿或出发点、必去地点，以及饮食偏好；系统安排景点、午晚餐和交通，并允许用户拖动、锁定、替换与撤销。

首版建议限制为一个城市、2—3 日自由行，人工维护约 50 个候选景点及必要事实。城市待用户确认，杭州仅作为此前讨论的示例，不写死为正式目的地。

### 首版范围

- 首页／探索、新建计划、规划工作台、只读分享。
- 地点搜索、地图联动、步行及公交／地铁分段。
- 景点开放与预约提示；午餐、晚餐主选及备选。
- 天气风险提醒、室内替代方案的预览与确认。
- 拖拽调整、锁定地点／时间、冲突提示、版本撤销。
- 分类预算：跨城交通、市内交通、住宿、餐饮和门票。
- 手动录入铁路／航班的出发、到达、返程时间及车站／机场，参与接驳和时间约束。
- 保存与可撤销的只读分享；无需先建设完整账号体系。

### 待验证扩展

- 美团个人开发者 MCP 的餐饮搜索、详情或评论能力。
- 聚合数据铁路时刻、席别票价和余票查询。
- 航班时刻／动态查询；实时机票报价另行评估供应商。
- 基于授权评论的证据化摘要。

这些能力默认关闭，不作为首版运行依赖。未取得权限不显示“已接入”。

### 不做

出票、支付、退改签、酒店预订、社区、多城市自动规划、未经许可的平台评论抓取、实时景区客流监测。首版不引入微服务、多 Agent 或大型向量数据库。

## 2. 技术栈

采用单仓库、模块化单体，前后端统一 TypeScript。

| 层次 | 选型 | 职责 |
| --- | --- | --- |
| Web 与服务端 | Next.js App Router、React、TypeScript | 页面、同源 Route Handlers、服务端编排 |
| 样式与组件 | Tailwind CSS、shadcn/ui | 一致的交互与响应式界面 |
| 地图 | 高德 JS API 2.0 | 标记、真实路线与地点联动 |
| 拖拽与状态 | dnd-kit、Zustand、TanStack Query | 拖拽、未保存草稿、服务端数据请求 |
| 数据校验 | Zod | 表单、API、供应商响应与模型结构化输出 |
| AI | 服务端原生 OpenAI 兼容 HTTP；默认 DeepSeek | 当前为真实地点推荐，后续需求解析与修改提案 |
| 持久化 | PostgreSQL、Drizzle | 行程、版本、分享权限、人工资料 |
| 测试 | Vitest、Playwright | 规划器、适配器、工作台交互 |

上述为架构选型，按阶段实施；已安装依赖与精确版本见 `package.json` 和锁文件。shadcn/ui、拖拽、数据库等后续模块尚未引入，不把选型写成已完成；AI 当前直接使用原生 fetch 接 OpenAI 兼容格式，没有安装模型 SDK。

## 3. 总体架构

```text
浏览器：表单 + 行程时间轴 + 地图 + 详情 + 预算／天气
  │ 同源 API；浏览器不携带供应商私密凭据
  ▼
Next.js Route Handlers
  │ 输入校验、所有权校验、限流、请求标识
  ▼
应用服务：生成计划 / 提出修改 / 预览 / 确认 / 分享
  ├─ AI：理解需求、解释事实、输出受约束的修改操作
  ├─ Planner：候选筛选、时间窗排程、餐饮插入、局部优化
  ├─ Validator：时间、开放、交通、预约、预算与锁定检查
  ├─ Providers：高德 / 天气 / 人工资料 / 可选铁路、餐饮、航班
  └─ Repositories：PostgreSQL + 版本与权限
```

依赖方向：`UI → HTTP → services → domain / providers / db`。领域算法不依赖 React、Next.js、模型 SDK 或供应商原始响应；供应商适配器不直接修改行程。

### 规划数据流

1. 表单或自然语言输入通过 Zod 校验；AI 解析结果回填表单，关键未知项由用户确认。
2. 人工资料和地点接口提供候选；读取可用天气及到达／返程约束。
3. 放入固定时间、必去地点、用餐和休息窗口，再做候选贪心插入。
4. 地理粗筛后只查询候选关键路段，按实际路线耗时重新排程。
5. 通过局部交换、跨天移动、替换改善偏好匹配、绕路、预算与天气风险。
6. 每次修改后校验；输出 `feasible / unverified / infeasible` 及原因，而非一律宣称可行。
7. AI 基于结果和来源解释推荐，不创造地点、开放时间、票价或天气。

高德公交方案总耗时已包含等车时间，归一化后不重复加算；另加的进站、接驳、休息缓冲要分别标明。门到门比较包括两端接驳和可调整的安检／出站缓冲，而不只比较列车或飞机运行时长。

### 餐饮规划

以午晚餐时间窗和前后地点筛选餐厅，检查营业、口味与预算；按“顺路、特色、预算友好”展示候选。

```text
额外绕路耗时 = 前一地点 → 餐厅 → 后一地点 − 前一地点 → 后一地点
```

真实路线耗时参与最终选择，直线距离只用于粗筛。无实时排队数据则显示未知；没有过敏相关可靠信息时不承诺安全，提示向商家确认。

### 修改、确认与撤销

```text
用户调整或 AI 请求
→ 生成 Proposal（携带 baseVersion）
→ 计算候选行程、校验、展示前后差异
→ 用户确认
→ 服务端复验与原子提交新版本
```

- AI 只输出允许的操作，例如移动、替换、删除、调整停留时间，不直接写数据库。
- 候选地点必须来自已有候选 ID；禁止提交模型自创 ID。
- `baseVersion` 不匹配返回版本冲突，重新预览，不覆盖其他修改。
- 确认时复验锁定、权限与所依赖数据的新鲜度；变化影响结果则要求重新预览。
- 地点锁与时间锁分开表达；用户手动排序后不偷偷恢复算法排序。
- 撤销恢复历史内容并生成新版本，不删除已有版本记录。

## 4. 数据与接口契约

### 领域模型

| 模型 | 核心内容 |
| --- | --- |
| TripInput | 城市、日期、人数、偏好、预算口径、起终点与饮食限制 |
| Place | 内部 ID、供应商 ID、坐标及坐标系、分类、入口、开放、预约、费用、室内外属性 |
| Evidence | 来源 URL／标识、来源日期、查询日期、许可备注、数据性质 |
| TransportLeg | 起终点、方式、出发时刻、耗时、费用、换乘、线路及来源 |
| IntercitySegment | 铁路／航班、完整出发到达日期时间、车站／机场、用户录入或接口来源 |
| WeatherSnapshot | 有效时段、日级／小时级粒度、更新时间、地点及来源 |
| ReviewInsight | 授权原文证据 ID、摘要、适用人群、时间；无证据不生成 |
| ItineraryItem | 景点／餐饮／休息／跨城节点、时间窗、停留时长、地点锁和时间锁 |
| PlanVersion / Proposal | 行程快照、前一版本、修改操作、基准版本、校验报告 |
| BudgetSummary | 各分类金额、每人／总额、估算区间、未知费用项 |
| GuestSession / ShareLink | 匿名编辑权限、分享快照、令牌摘要、到期与撤销状态 |

数据性质采用 `provider / curated / user / estimate / fixture`，并记录来源和有效时间；缺失值是 `null`，不是零。供应商数据也不等于绝对正确：每个关键字段的来源和时效可单独追踪。

- 金额使用整数分并记录币种；预算默认包含跨城往返、住宿、餐饮、门票与市内交通，不含购物，允许用户关闭跨城计入。
- 人均餐饮费用按人数计算；跨城票价按实际录入或查询席别计算；未知费用使总额成为不完整估算。
- 保存 ISO 日期时间与时区；首版国内行程使用 `Asia/Shanghai`，跨午夜班次必须保留到达日期。
- 高德路线／展示坐标使用 GCJ-02；其他坐标保留原始坐标系。天气坐标按供应商要求转换，不能默认为与地图一致。
- 开放和预约规则保留有效日期；“需预约”不等于“已预约”。
- 拥挤度仅做规则估计，显示“非实时监测”；不得把道路拥堵等同于景区客流。

### 供应商边界

按能力定义 `PlaceProvider`、`RouteProvider`、`WeatherProvider`、`RestaurantProvider`、`RailProvider`、`FlightProvider`，避免把全部能力塞进一个万能客户端。

适配器返回经校验的领域数据和状态：`ok / not_configured / permission_denied / unavailable / out_of_range`。异常、空结果、缺字段分别处理，HTTP 200 不代表业务成功。可选接口未开通时关闭对应入口；人工录入始终标明来源。

AI 工具仅封装可信服务：`searchPlaces`、`getPlaceFacts`、`getWeather`、`calculateRoute`、`proposePlanChanges`。评论和地点文本都是不可信内容，不可作为改变工具权限的指令。

### 计划中的 HTTP API

| 接口 | 用途 |
| --- | --- |
| `GET /api/places` | 有边界的地点／餐饮搜索 |
| `GET /api/weather` | 天气与粒度、有效范围 |
| `POST /api/routes` | 指定时刻的路段规划 |
| `POST /api/plans` | 当前生成路线草稿，不持久化；后续再加保存 |
| `GET /api/plans/:id` | 读取有权限的行程 |
| `POST /api/plans/:id/proposals` | 生成修改预览，不覆盖已保存版本 |
| `POST /api/plans/:id/proposals/:proposalId/apply` | 复验并确认修改 |
| `POST /api/plans/:id/restore` | 将指定历史版本恢复为新版本 |
| `POST /api/plans/:id/shares` | 创建只读脱敏快照链接 |
| `DELETE /api/plans/:id/shares/:shareId` | 撤销分享 |
| `GET /api/shares/:token` | 读取有效的只读快照 |

当前实现 `GET /api/places`、`POST /api/routes`（步行）、`POST /api/plans`（只生成草稿）与 `POST /api/recommendations`（AI 从真实候选推荐）。其余接口尚未实现。铁路和航班 API 路由等实际验证通过再添加。

## 5. 页面与状态

- 桌面工作台：左侧每日行程、中部地图、右侧详情；天气与预算为辅助信息。
- 窄屏：行程／地图切换，详情采用抽屉；拖拽提供键盘及按钮替代。
- 地点悬停、选中与地图标记联动；替换餐厅同时预览时间、路线和费用变化。
- TanStack Query 管服务端状态；Zustand 只管理草稿、选中项和预览 UI，不复制另一份服务端缓存。
- 生成与刷新均有加载、空态、错误和重试状态；保留用户输入。
- 核心表单、分享内容可服务端渲染；地图及拖拽按需使用客户端组件。

## 7. 安全、配额与降级

- 私密凭据只在服务端配置；地图 JS Key 属于公开客户端标识，使用独立 Key、域名限制及供应商推荐的安全代理配置。Web 服务 Key 不能放入 `NEXT_PUBLIC_*`。
- 所有供应商请求有超时、并发上限、有限重试和调用计数；401／403 不盲目重试。不对所有候选地点请求全量两点路线矩阵。
- 仅在许可允许时缓存／保存供应商数据；TTL 和可保存字段在账号验证后确定。历史快照也须遵守许可，不能借版本保存绕过存储限制。
- 没有路线时保留草稿并标明“交通未校验”，不把直线距离包装成真实路线。天气缺失显示未知，不自动编造雨天。
- 演示模式只能明确选择，使用独立 fixtures 并醒目标注；生产错误不静默切换到假数据。
- 匿名编辑使用高熵令牌、服务端摘要校验、HttpOnly／SameSite Cookie（生产启用 Secure）；写接口校验来源以防 CSRF。不可只凭行程 ID 或客户端 ownerId 授权。
- 分享使用独立可撤销令牌和脱敏快照，默认不包含姓名、联系方式、精确住宿地址、订单与票据；链接不赋予编辑权限。
- 限制外部请求目标为已配置供应商，不能让模型或用户指定任意 URL；日志脱敏，不记录完整凭据、票据或私密位置。

## 8. 实施顺序与验收

| 阶段 | 交付 | 验收证据 |
| --- | --- | --- |
| 0：账号与资料 | 选定城市、人工资料、高德与天气凭据 | 脱敏真实响应、权限与展示／存储许可记录 |
| 1：最小闭环 | 表单 → 地点 → 路线 → 天气 → 日程 | 至少一个真实 2 日案例；来源、未知与冲突正确展示 |
| 2：工作台 | 拖拽、锁定、餐饮替换、预算 | 修改只影响必要路段，锁定不丢失；键盘可操作 |
| 3：AI 修改 | 解析、提案、预览、确认 | 模型无效 ID 被拒绝；冲突不覆盖；确认前不写入修改 |
| 4：持久化分享 | 版本、撤销、脱敏分享 | 越权测试、撤销分享和并发版本测试通过 |
| 5：可选数据 | 铁路／餐饮／航班接口 | 每项单独完成账号实测后启用，不阻塞核心闭环 |

规划器测试包括：闭馆、最晚入场、固定预约、餐厅停业、预算缺项、返程过早、跨午夜班次、锁定冲突、天气超出范围、路线失败和时间窗不可行。供应商测试覆盖缺字段、业务错误、鉴权失败与限流。

端到端主线：生成两日游 → 锁定必去地点 → 天气风险提醒 → 预览室内替代及顺路餐饮 → 确认 → 撤销 → 分享；真实天气与演示天气不得混淆。评估对照纯模型攻略、仅距离排序和完整规划方案，记录时间冲突、交通耗时与人工修改次数。

## 9. 当前仓库与待确认事项

首轮已实现表单、真实地点／步行路线和响应式路线草稿，已完成离线浏览器与实际应用 HTTP 联调。2026-10-13 通过本地 `POST /api/plans` 查询 3 个地点与 1 条步行路线，见 [脱敏实测摘要](docs/evidence/app-smoke-2026-10-13.json)。该次 HTTP 成功不等于地图或完整行程验收；已接通搜索选择、地图点选弹窗和 AI 兴趣推荐的混合地点清单；AI 已经用户授权的单次真实联调（`deepseek-flash` 返回 4 个真实候选），桌面真实底图与用户点选已通过单独复验；完整餐饮排程、天气、持久化和分享尚未实现。

本地开发：`npm ci --ignore-scripts`（首次安装），保留已有 `.env.local`，然后 `npm run dev`，访问 `http://127.0.0.1:3000`。检查命令为 `npm run check`、`npm run build` 与 `npm run e2e`；当前实际结果见 [测试记录](docs/testing.md)。

界面当前严格使用已批准的 Figma Light 配色，不再跟随系统自动套用未批准的 Dark 候选值。

AI 使用服务端 `OPENAI_API_KEY` 或 `DEEPSEEK_API_KEY`，支持进程环境或 `.env.local`；可设置 `OPENAI_BASE_URL` 和 `OPENAI_MODEL`，默认 `https://api.deepseek.com`、`deepseek-flash`（按当前官方文档核对）。不要使用 `NEXT_PUBLIC_*`。每次推荐消耗真实地点与模型配额，不保证免费；缺凭据或无效输出明确失败，不回退假推荐。自定义与 AI 两种入口共用最多六个地点的清单，推荐需手动添加，不覆盖已选点；搜索返回候选供明确选择，按 POI ID 重新核对。地图需先搜到城市内地点作为中心，用户点位保留用户来源，地址与开放未知，不发送给模型。

代码使用两空格缩进、完整控制流大括号与展开的 JSX／CSS；`npm run format` 格式化，`npm run format:check` 检查，后者已纳入 `check`。E2E 在 3100 端口使用独立 `.next-e2e` 目录并清空所有支持的地图与模型凭据，不复用真实开发服务。

`npm run smoke:live` 需先启动 3000 开发服务，显式消耗真实高德配额（3 次地点搜索、1 次步行算路），不属于离线检查。脚本发现当天证据已存在时会拒绝重复请求；不要把它当作无成本测试反复运行。另有显式 `npm run smoke:recommendation`（一次地点搜索＋模型请求，再检验 JS 地图）；成功或失败均保存当天 attempt，禁止无授权重复计费。`npm run smoke:map` 仅验证地点搜索与地图、拦截模型请求，也有独立当天防重复标记。

服务端 `AMAP_WEB_SERVICE_KEY`、独立浏览器 `NEXT_PUBLIC_AMAP_JS_KEY` 和私密 `AMAP_JS_SECURITY_CODE` 已在本地配置，但配置不等于底图验收。用户已确认安全码控制台重置并更新本地；首次实测的空画布已通过给共享地图容器补明确宽高修复：SDK 设 relative 后仍有 710×360 尺寸，底图与点选添加在独立授权的真实桌面复验中通过；真实窄屏与工作台路线联动还未另行验收；不要把值发到聊天或覆盖已有 Web 服务 Key。安全码仅经同源 `/_AMapService` 代理注入，不传给页面；已检查构建客户端脚本和实际服务端 HTML，未发现两项私密凭据。未配置或加载失败时，不用假地图替代。初始化等待高德地图资源 `complete` 事件；20 秒内未就绪会区分脚本／底图超时并显示重试，而不是一直空白。地图代理接受同协议、同端口的 localhost／127.0.0.1 别名，仍拒绝跨站调用。

当前仅在本机运行，不作上线准备完成的承诺。草稿只保存在页面内存，刷新即丢失；供应商结果不缓存、不入库。API 有进程级调用预算与并发保护，但不是生产分布式限流。
