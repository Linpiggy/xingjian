# 行间 · 演示视频脚本

目标时长约 7 分钟（赛事要求 5–8 分钟），1080p MP4，普通话讲解，建议加字幕。

## 录制准备

- 浏览器窗口调整为 1920×1080，缩放 100%，隐藏书签栏；系统关闭通知。
- 先在 `.env.local` 配好高德与模型密钥（演示门票核对、照片识景时还需 `TAVILY_API_KEY`、`VISION_API_KEY`），用 `npm run build && npm run start` 启动生产模式，页面更流畅。
- 提前清空浏览器本地数据，让“我的行程”从空白开始；准备一张旅行照片（如西湖航拍）放在桌面。
- 真实规划约 1 分钟：录制时完整录下，剪辑时把中段加速到 2–4 倍，保留开头的工具调用和逐日出现的效果。
- 讲解语速约每分钟 220 字，下表讲解词总计约 1500 字。

## 分镜

| 时间 | 画面与操作 | 讲解词 |
| --- | --- | --- |
| 0:00–0:25 | 片头：首页首屏，标题逐行升起，照片视差 | 大家好，我们的作品叫“行间”，一个会做功课的 AI 旅行规划 Agent。做一份靠谱的攻略往往要在地图、点评、天气和车票之间来回切换好几个小时；直接问大模型虽然快，但地点可能是编的，时间也常常排不开。行间想解决的就是这个问题。 |
| 0:25–1:05 | 缓慢向下滚动，展示“做功课的流程”吸顶叙事：检索 → 查地点 → 看天气 → 路线随滚动描出 → 校验修正 | 行间不是一段聊天回复，而是一套完整的工作流程。大模型负责理解需求和做取舍；地点、路线、车次、天气这些事实交给高德地图等工具；时间和预算交给确定性算法计算；最后由服务端逐条校验，发现闭馆、赶不上车这类问题，就退回给 Agent 自己修改。 |
| 1:05–1:45 | 滚到表单。点“用一张照片找灵感”，上传西湖照片，展示识别结果，点“去杭州”自动填入 | 先看多模态输入。我在网上看到一张很美的湖景照片，但不知道是哪里。上传之后，视觉模型认出这是西湖三潭印月，给出了风格标签和推荐城市，一键就把目的地、兴趣和补充说明填好了。照片在浏览器里压缩并去掉了定位信息才上传。 |
| 1:45–2:10 | 继续填写：出发城市“上海”、2 天、情侣、必去“灵隐寺”、口味“不吃辣”；点击备注框的话筒，说“想看一次西湖日落” | 再补充几项：从上海出发，玩两天，必去灵隐寺，不吃辣。备注也可以直接说话输入。点击生成。 |
| 2:10–3:10 | 规划页：左侧 Agent 轨迹逐条出现（查询车次、检索知识库、并行搜索地点、空间编排、确定住宿、周边餐厅、编排第 1 天……），右侧地图上候选点陆续出现，逐日章节依次生成（中段加速） | 这是 Agent 的工作现场。它先查询上海往返杭州的高铁，选定车次；然后检索知识库，了解灵隐寺要分开买票、西湖适合分片区游；接着在同一轮里并行搜索多个关键词，地图上的灰点就是实时搜到的候选地点。之后它用聚类算法把景点分到两天，在行程重心附近选酒店，再在每天的景点附近找餐厅。注意这里：第二天的安排太满，服务端算出赶不上原来的返程车，Agent 自己改选了更晚的一班，冲突就消失了。 |
| 3:10–4:00 | 手册生成完成：封面 → 总览（天气、预算、往返车次卡片、住处）→ 第 1 天路线图 → 时间轴：车次到站、出站前往第一站、景点卡片、推荐菜“招牌”标签、订座电话 | 几十秒后，一本旅行手册就生成了。总览里有天气、人均预算构成、往返车次和每个席别的票价，旁边是去 12306 购票的入口；住处也说明了为什么选在这里。每天以一张真实路线图开篇，时间轴从到站开始，每一站有实景图、推荐理由和贴士。餐厅的推荐菜优先取自高德收录的招牌菜，标着“招牌”，还有订座电话。门票如果联网核对过，会显示官方来源链接。 |
| 4:00–4:30 | 点右下角“地图”打开全屏地图，点列表中的站点，地图高亮；点“看详情”跳回卡片 | 点右下角的地图按钮可以全屏查看当天路线，左边列表和地图联动，点“看详情”就回到对应的站点。 |
| 4:30–5:15 | 在对话栏“调整行程”输入“第二天下午加一个博物馆”，展示调整过程与“已调整”说明；点“撤销”恢复 | 不满意可以直接说。比如“第二天下午加一个博物馆”。Agent 只重排受影响的那一天，并告诉我改了什么。改了不喜欢，一键撤销。 |
| 5:15–5:45 | 对某一站点“锁定”，再点另一站“换一个”，在候选中选一家餐厅，几秒后时间重新计算 | 也可以自己动手：锁定的站点，AI 调整时不会动它；“换一个”会从 Agent 搜过的候选里按距离推荐，选好后用真实路线几秒钟重新排出时间，这一步不需要调用大模型。 |
| 5:45–6:20 | 切到“问问 AI”，提问“灵隐寺要提前预约吗？附近有没有便利店？”，展示工具步骤、流式回答与来源标签 | 出发前还有疑问，可以切到“问问 AI”。它会结合这份行程，查知识库、联网核对门票、搜索附近设施，边查边答，最后标出用到了哪些来源；不确定的事情会明确说不确定，并建议去官方渠道核实。 |
| 6:20–6:50 | 点“分享”：展示只读链接和长图；新标签页打开链接，展示分享页与“存到我的行程” | 最后是分享。行程被压缩进链接的 # 部分，服务器不会保存，也看不到内容；朋友打开就能看到完整手册，还可以存成自己的行程继续改。同时会生成一张带实景图的长图，方便发到群里。 |
| 6:50–7:20 | 回到首页，切换手机尺寸（或用手机录屏）展示响应式；收尾画面显示核心数据 | 整个应用适配手机。总结一下：行间用 Agent 加工具调用、RAG 知识库和确定性算法，把旅行攻略变成了可执行的行程。我们的对照评测里，直接问大模型只有 83% 的地点能在地图上找到，而行间达到 98%，交通衔接没有一段排不开。谢谢观看。 |

## 剪辑提示

- 片头和结尾各加 2 秒作品名称字卡：“行间 · AI 旅行规划 Agent”。
- 规划过程是 AI 能力的核心展示，加速时保留轨迹面板清晰可读；可在“改选返程车次”处放大局部并加字幕强调“自我修正”。
- 字幕与讲解词一致；涉及数据（83% / 98%）时可在画面上叠加对照表。
- 背景音乐音量保持在讲解声音的 15% 以下。
