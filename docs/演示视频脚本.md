# 行间 · 演示视频脚本

目标时长 7 分 30 秒左右（赛事要求 5–8 分钟），1080p MP4，普通话讲解，配字幕。讲解词约 1400 字，按每分钟 220 字计约 6 分半，加上操作停顿约 7 分半；超时优先删减第 8、11 段。

## 录制准备

- 浏览器窗口 1920×1080，缩放 100%，隐藏书签栏，关闭系统通知。
- `.env.local` 配好高德、DeepSeek 与 `TAVILY_API_KEY`（门票联网核对需要），用 `npm run build && npm run start` 启动生产模式。
- 清空浏览器本地数据，让“我的行程”从空白开始；桌面放一张西湖航拍照片。
- **先完整彩排一次**：真实规划约 1 分钟，每次 Agent 的决策不完全相同。彩排时记下本次是否出现“冲突 → 修改 → 通过”的轨迹，正式录制按实际画面选择第 4 段的讲解词（下文给了两个版本）。
- 第 11 段需提前在 Claude Desktop 或 Cursor 中按 README 配好 `xingjian-travel` MCP Server，并确认工具列表能加载。
- 第 12 段的对照评测表直接截取技术文档 6.3 节或 README；架构图截取技术文档图 2。
- 规划过程录制完整，剪辑时中段加速 2–4 倍，保留开头几步工具调用和逐日出现的效果。

## 剪辑提示

- 片头、结尾各加 2 秒字卡；结尾字卡写作品名、团队名与仓库地址。
- 第 4 段是 AI 能力的核心证据：加速时保证轨迹面板文字清晰；在“知识库来源”和“校验退回 / 重新提交”处放大局部，叠加字幕“Function Calling”“RAG 检索”“服务端校验 → 自我修正”。
- 每段开头可在左上角叠加小标签，对应上表“主要对应的评分点”，方便评审对照，例如“多模态：图像 + 语音”“MCP 工具集成”。
- 字幕与讲解词一致；第 12 段的数字在画面上同步显示对照表。
- 背景音乐音量不超过讲解声音的 15%；规划等待段可适当提高音乐音量。
- 导出 MP4（H.264），分辨率 1920×1080，导出后确认时长在 5–8 分钟之间。
